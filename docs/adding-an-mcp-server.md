# Adding an MCP server to an existing Spring Boot service

Developer guideline. Verified against Spring Boot 4.1.1 + Spring AI 2.0.1.

## Minimal adaptation: three changes

**1. Dependency**

```groovy
implementation platform('org.springframework.ai:spring-ai-bom:2.0.1')
implementation 'org.springframework.ai:spring-ai-starter-mcp-server-webmvc'
```

**2. One property** — the transport is served at `/mcp`

```properties
spring.ai.mcp.server.protocol=STREAMABLE
spring.ai.mcp.server.name=my-service
```

**3. Annotate a method you already have**

```java
@Service
public class OrderService {

    @McpTool(description = "Look up an order by its id.")
    public Order findOrder(String orderId) { ... }
}
```

That is the whole floor. No new class, no `ToolCallbackProvider`, no config class,
no registration code. Startup logs `Registered tools: N`.

## Does it have to be a `@Service`?

**No. Any Spring bean works.** Verified by experiment — all of these were discovered
and callable:

| Holder | Discovered |
|---|---|
| `@Service` | yes |
| `@Component` | yes |
| `@RestController` | yes |
| Plain class registered via `@Bean` | yes |
| Class that is not a bean | **no** |

Being a bean is the only requirement. Static methods register too.

## Defaults worth knowing

| | Default | Override |
|---|---|---|
| Endpoint | `/mcp` | `spring.ai.mcp.server.streamable-http.mcp-endpoint` |
| Tool name | the Java method name | `@McpTool(name = "...")` |
| Parameters | **all required** | `@McpToolParam(required = false)` |
| Discovery | annotation scanner, on | `spring.ai.mcp.server.annotation-scanner.enabled` |

## Four traps

**1. `protocol` must be explicitly set.** The auto-configuration is gated on the
property being *present*, not on the properties-class default. Omit it and `/mcp`
returns 404 with no error in the logs.

**2. Every parameter is required by default.** An optional argument needs
`@McpToolParam(required = false)` or clients cannot omit it.

**3. Jackson `@JsonValue` enums produce a tool that cannot be called.** The schema
generator emits Java constant names (`FIRE`) while the deserializer accepts only the
`@JsonValue` wire value (`fire`), so *neither* spelling works. This hits every enum
generated by openapi-generator. It registers fine, lists fine, and fails only when a
model actually calls it. Use a plain enum at the MCP boundary and map to the
generated one.

**4. The annotation is the only gate.** There is no visibility or signature filter.
Annotating a static helper publishes it as a first-class tool, and the method name
becomes your public contract — an ordinary rename is a breaking API change.

## Annotate in place, or add an MCP class?

Default to annotating in place. Add a thin MCP-facing class only when one of these
applies:

- a parameter type whose schema and deserializer disagree (trap 3 — assume this if
  your models are generated from an OpenAPI spec)
- optional parameters, and you do not want `@McpToolParam` in domain code
- method names or return shapes you do not want as a public contract
  (`Map<Double, List<T>>` is valid but poor for a model to read)
- a policy of keeping Spring AI imports out of domain classes

Fewer files versus a stable contract. Nothing else.

## Before shipping a tool

- [ ] `tools/list` shows the schema you expect (check `required` and any enums)
- [ ] `tools/call` succeeds with the exact values the schema advertises
- [ ] Description says *when* to use the tool, not just what it does
- [ ] No internal helper got published by accident

```bash
curl -s -X POST http://localhost:8080/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"curl","version":"1"}}}'
```

Reuse the returned `Mcp-Session-Id` header for `tools/list` and `tools/call`.

## Behind an ingress

Streamable HTTP replies with server-sent events. Proxies need buffering off, or
responses arrive chunked, late, or never:

```nginx
location /mcp {
    proxy_pass http://backend;
    proxy_http_version 1.1;
    proxy_buffering off;
    proxy_read_timeout 1h;
    proxy_set_header Connection "";
}
```
